# Reproducibility: what is claimed, what is recorded

A pinned seed does **not** make an LLM run reproducible everywhere. Ollama's own documentation promises only "the same text for the same prompt," and its issue tracker shows the limits: the same seed reproduces on the **same device, OS, Ollama build, model digest, and parallelism setting**, while a different GPU or quantization gives "similar but not identical" output, the first generation after a model loads can differ from later ones (the prompt cache), and `OLLAMA_NUM_PARALLEL > 1` changes batching (see [ollama#586](https://github.com/ollama/ollama/issues/586), [ollama#5321](https://github.com/ollama/ollama/issues/5321), and [arXiv 2506.09501](https://arxiv.org/abs/2506.09501) on BF16 batch-size variance). So Iago claims *recorded* reproducibility, not universal reproducibility:

- **Every artifact opens with a manifest line** naming the Iago version and git commit (with a dirty flag), a sha256 of the loaded technique library, the Ollama server version, the model's digest, quantization, and context length, every sampling option (`temperature`, `base_seed`, the per-trial seed rule, trial and step caps), the `OLLAMA_*` environment settings that change batching, the host platform, and a `judge_id` fingerprint of the scoring code. Two artifacts are comparable when those match; `iago compare` refuses artifacts scored by different judge code unless told otherwise.
- **Every `iago run` tries to disprove determinism instead of assuming it.** Before the main run, the runner sends a throwaway warm-up and then two open-ended probes, each twice, at the run's temperature and seed. It records the result of each pair, the overall `determinism.mismatch_detected`, and what the probes cost, and warns when any pair differs. The field is named for what the check can see: `true` means a mismatch was seen, `false` means none was seen **in those pairs**, `null` means it could not be determined. There is no value that means "this host reproduces," because the check cannot see that. `--no-determinism-check` skips it and records `null`, saving five short generations (about 800 tokens at the 160-token cap), but then the main run starts on a **cold** model, which a default run does not, since the probes warm it. The two modes are not the same experiment.
- **What the check is and is not.** Two open-ended probes, each fired twice; the manifest records which differed, at what position (`warm`, or `cold` if the warm-up itself failed), and what it cost. The check is **one-sided**: a mismatch proves this host is not bit-for-bit reproducible at these settings, while no mismatch proves only that those pairs repeated, never that the main run would. `null` means it could not run, neither pass nor fail, and a mismatch outranks a `null`. The probes are open-ended and capped at 160 tokens so that they *can* disagree (a short fixed echo cannot); two of them rather than one hedges against determinism that depends on the prompt, which the author's own host demonstrates below. They fire before the main run, after a throwaway warm-up, so no pair straddles the first-generation-after-load boundary. No mid-run sample is taken, because a probe injected into the main run's request stream would disturb the batching it is measuring. Sensitivity rises with temperature and tokens generated, so a clean result at temperature 0 is much weaker evidence than one at 0.8.
- **On the author's own host this check records a mismatch.** At seed 1337 on `llama3.1`, one probe differs and the other matches, reproducibly. Every report and `iago compare` run built from such an artifact says so in the output, not only in the manifest.
- **What is still not captured:** GPU model and driver, the exact llama.cpp build inside Ollama, and whether the working tree was clean (the commit is read from `.git` without shelling out, and a dirty flag needs a full index comparison, so it is reported `null` rather than guessed). Matching manifests mean *the recorded inputs match*, not that two runs are interchangeable. Treat a replay on another machine as a new run to compare, not a re-execution of the old one.
